# 安装与更新

[返回手册首页](index.md)

## 下载哪个版本

从 [GitHub Releases](https://github.com/PharmaRA/RATools-for-PDF/releases) 选择需要的 Windows 发布包。版本号和附件是否已发布，以该页面实际内容为准。

| 变体 | 启动程序 | 更新相关行为 |
| --- | --- | --- |
| 标准版 | `RATools-for-PDF.exe` | “关于”提供检查更新入口，也可能在启动时提醒重大更新 |
| NoUpdate 版 | `RATools-for-PDF-NoUpdate.exe` | 无更新检查入口，也不会在启动时执行 GitHub 更新检查 |

两种变体的选择主要影响更新能力。NoUpdate 不意味着不能由用户主动打开外部网页或通过其他 PDF 阅读器访问链接。

## 解压和第一次启动

1. 将完整 ZIP 解压到一个自己可写的专用目录，例如 `D:\Tools\RATools-for-PDF`。
2. 保留压缩包中的全部文件和子目录；不要只复制 EXE，也不要在压缩包预览窗口内直接运行。
3. 双击对应程序。Windows 发布包包含运行依赖，普通用户无需另装 Python；保留包内 qpdf 及其配套资源。
4. 点击“关于”，记录实际版本。
5. 点击“全局设置”，确认“覆盖原始文件 (不推荐)”未选中。可以设置默认保存位置。
6. 用一份工作副本完成[第一次处理 PDF](quick-start.md)。

程序使用本地 `settings.ini` 保存规则、图像参数、输出位置、外观和处理性能等设置。打包运行时通常位于可执行文件所在目录。若设置无法保存，先检查软件目录是否可写；不要因此将所有文档都放入程序目录。

## 更新已有版本

标准版可打开“关于 → 检查更新”，再使用“打开发布页”查看发布说明和附件。更新检查不等于已经安装新版本。

建议先结束正在进行的任务，导出需要保留的日志、审计包和处理配置，再将新版本完整解压到新目录。运行并确认版本后，用少量副本检查常用流程。

需要迁移规则时，使用“配置管理 → 导出配置 (JSON)...”，在新版本中导入。该 JSON 不携带输出目录、覆盖原文件、并行数量、超时和主题；这些设置需要在新版本中单独确认。详见[配置管理](profiles.md)。

## 依赖和平台

当前发布和主要验证环境为 Windows。页面处理使用 PyMuPDF，部分操作需要 qpdf，包括版本转换、线性化、安全中心，以及部分结构处理。找不到 qpdf 时，优先检查是否完整解压并保留资源，而不是随意从其他软件目录复制单个 DLL。

字体复检在本机执行；实际嵌入字体需要具备相应能力的外部程序。仅安装 Acrobat Reader、或成功打开 Acrobat，并不保证具有印前检查修复能力。

源码运行和开发环境安装见[项目 README](../../README.md)。macOS/Linux 源码能否运行与 Windows 发布包的可用范围是不同问题，本手册不作完整兼容承诺。

## 启动异常的处理顺序

1. 确认 ZIP 已完整解压，运行的是正确变体的 EXE。
2. 将完整软件目录放到可写的本地位置，避免仍在下载或同步中的目录。
3. 记录报错原文及版本，检查系统是否拦截了附件中的运行文件。
4. 若程序可启动但某个功能失败，到[常见问题](faq.md)按具体功能排查。
