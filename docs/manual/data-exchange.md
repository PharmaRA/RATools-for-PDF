# 书签与链接数据导入导出

[返回手册首页](index.md)

入口分别是“书签管理 → 书签数据导入/导出...”和“超链接处理 → 链接数据导入/导出...”。向导处理整个主队列，不是只处理选中行；不需要再点击主窗口“开始处理”。

书签使用 CSV，页面链接使用 JSON。它们是导航数据，不是完整 PDF 内容，也不包含可用来重建整份文档的页面文本或图像。

<a id="wizard"></a>
## 向导的通用步骤

1. 把本次需要导入或导出数据的 PDF 加入队列，移除其他文件。
2. 打开对应向导，选择“导出数据”或“导入数据”。
3. 选择数据目录；链接向导还需选择链接范围，导入时选择覆盖或增量。
4. 查看“匹配预览”中的 PDF、类型、状态和数据文件路径。
5. 导出时确认哪些文件“将生成”；导入时确认“已匹配”和“未找到”的数量。
6. 点击“开始导出”或“开始导入”，等待结果并检查日志。

未匹配的数据文件会被跳过；全部未匹配时不能完成有效导入。文件名匹配只说明找到了数据，不证明目标页码、坐标或链接内容正确。

<a id="paths"></a>
## 文件名和目录怎样对应

`report.pdf` 对应 `report_bookmarks.csv` 或 `report_links.json`。同批不同目录的同名 PDF 按相对目录分开，例如：

```text
输入：D:\资料\a\report.pdf
      D:\资料\b\report.pdf
数据目录：D:\导航数据

书签导出：D:\导航数据\a\report_bookmarks.csv
          D:\导航数据\b\report_bookmarks.csv
```

导入时选择 `D:\导航数据`，并保持本次输入的相对目录关系。若换了队列集合，公共目录可能变化，务必以向导预览的完整数据路径为准；不要只检查某处存在同名 CSV/JSON。

导入后的 PDF 放在**队列首个 PDF 所在目录下的 `RATools_导入完成`**，内部再保留相对目录层级。这个位置不是数据目录，也不是主批处理的 `RATools_Output`。重复运行可能替换同名结果，重要输出应先另行归档。

<a id="bookmarks"></a>
## 编辑书签 CSV

建议先导出真实 PDF 的 CSV，再在副本上编辑。当前导出为 UTF-8 BOM 编码，包含：

| 字段 | 含义 |
| --- | --- |
| `Level` | 书签层级，顶层从 1 开始 |
| `Title` | 显示标题 |
| `Page` | 面向阅读者的页码，从 1 开始 |
| `Kind` | 动作类型数值；保留导出值，不按名称自行猜测 |
| `Uri` / `File` | URI 地址或外部文件目标 |
| `TargetPage` | 动作目标页索引，从 0 开始，与 `Page` 计数不同 |
| `ToX` / `ToY` | 跳转坐标 |
| `Zoom` | 跳转缩放；0 表示承前缩放语义 |
| `NewWindow` | 外部动作是否新窗口，使用 `true` / `false` 或支持的空值 |
| `NamedDest` | 命名目标 |

只需要内部页书签时，也支持旧的三列表格。例如目标 PDF 至少有三页：

```csv
Level,Title,Page
1,研究报告,1
2,研究方法,2
2,研究结果,3
```

将该文件保存为与目标 PDF 对应的 `_bookmarks.csv` 后导入。导入会用这份目录**重建书签树**，不是给旧目录追加三项；不要遗漏需要保留的书签。

注意事项：

- 第一项层级会归一为 1，后续层级跳跃会受限制；不要依赖自动修正来设计目录。
- 超出内部页码范围的值可能被限制到有效范围，仍需人工核对章节目标。
- 含 `Kind` 的完整数据中，`TargetPage` 可能决定实际动作；只改 `Page` 不一定改变真正跳转目标。需要移动内部目标时应同时理解两列关系。
- CSV 标题包含逗号时需正确引用，例如 `"结果,讨论"`。使用电子表格另存时保留 UTF-8 CSV，不要保存成 XLSX 后仅改扩展名。
- 只有表头、没有书签数据行的 CSV 会清空现有书签；导入前检查数据行数。
- 不支持的动作可能导致导出/导入失败；应保留错误提示，不要自行删列后认为完整导航仍被保留。

导入后打开输出 PDF，核对标题、层级、页码和外部/命名目标。

<a id="links"></a>
## 编辑链接 JSON

JSON 顶层为链接记录数组。导出数据可包含 `page_index`、`rect`、`kind`、`uri`、`file`、`target_page`、`zoom`、`to`、`new_window` 和 `quad_points`。

`page_index` 与目标页索引从 0 开始；`rect` 是链接区域坐标，`quad_points` 用于描述多行链接的点击区域。建议以真实导出作为模板，只修改已理解的目标字段。页面经过重排、缩放或换版后，旧坐标不会自动适应新布局。

### 链接范围

“全部链接”包含内部与外部链接。“仅外部链接”包含 URI、外部 PDF 跳转和启动外部文件等受支持类型，不包含文档内部跳转。

### 覆盖与增量

| 范围与模式 | 对已有链接的处理 |
| --- | --- |
| 全部链接 + 覆盖 | 清除原有页面链接，再按 JSON 重建 |
| 仅外部链接 + 覆盖 | 清除范围内的外部链接，保留内部跳转，再导入外链 |
| 全部链接 + 增量 | 保留旧链接，按位置重叠判断跳过重复区域，补充其他记录 |
| 仅外部链接 + 增量 | 只导入外链；仍按既有链接区域判断重叠 |

“增量”不是按 URL 合并，也不是用新地址更新相同区域的旧链接。相同点击区域里已有链接时，新目标可能被跳过。若目标是替换地址，应采用适当范围的覆盖，并先确保 JSON 包含需要保留的完整数据。

空数组配合覆盖会清除对应范围的链接。越界页或部分无法插入的记录可能未进入输出；任务结束不保证每条记录都恢复成功，必须抽查数量、页面区域及跳转目标。

## 适合与不适合的使用场景

适合对同版面文档交换导航数据、批量编辑书签标题，或在充分理解路径和坐标的前提下修改链接目标。不适合把一份旧 PDF 的全部导航直接套到页数、版式都已改变的新稿，然后仅凭导入成功判断正确。

本向导与主批处理是独立流程；其结果应自行复核，不能假定自动包含主批处理同样的计划预览和最近批次审计事实。
