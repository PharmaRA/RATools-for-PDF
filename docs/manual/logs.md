# 日志、结果与审计包

[返回手册首页](index.md)

入口：主窗口底部“日志”。日志用于查看文件处理和检查记录；审计包用于保存最近已结束主批次的结构化事实，二者范围不同。

<a id="view"></a>
## 查看、筛选与搜索

日志窗口显示总记录、成功、失败、建议处理和跳过统计。可使用“全部”“仅成功”“仅失败”“仅预检”“仅跳过”筛选，再按文件名、状态或结果关键字搜索。

汇总表包含时间、状态、文件、耗时、输出和结果/变化。选中一行查看详细记录。总记录数可能包含不同操作或多次记录，不应直接当作本轮唯一文件数量。

<a id="results"></a>
## 结果状态和规则事实

| 看到的内容 | 可以判断什么 |
| --- | --- |
| 处理完成 | 该文件按当前管线完成并发布；仍需检查内容 |
| 处理失败 | 查看引擎、超时、输出资源或验证等具体原因 |
| 已跳过 / 已停止 | 没有继续按原计划完成；不应算成成功输出 |
| 建议处理 | 预检提示，需要决定后续操作 |
| 规则已选择/计划执行 | 用户意图或预览决定，还不是实际修改证明 |
| 规则执行但没有变化 | 可能已满足要求，或本次没有可修改对象 |
| `unknown` / `null` | 对该事实没有足够观测，不能解释为没有问题 |
| `not_verified` | 没有完成对应独立验证，不能解释为验证通过 |

当前独立后置检查只覆盖部分规则，例如标题、A4/Letter 几何、URI 删除、普通批注删除和附件删除。复合规则不能只凭一个局部条件就认定整条通过。签名有效性始终需要独立检查。

更多字段含义见[规则结果技术说明](../rule-results.md)。

<a id="exports"></a>
## 导出日志和预检结果

点击“导出日志”，在保存类型中选择：

- `CSV Summary`：便于按文件、状态、耗时和变化整理表格；
- `Text Files`：保存日志文本，适合查看检查明细和错误上下文。

日志导出使用本窗口背后的记录，不只导出当前筛选后看到的行。分享前应检查文件名、路径及检查内容是否包含不适宜外发的信息。

“导出预检结果”输出最近一次预检 CSV，包括建议、错误、字体、批注和失效引用细节；它不是全部历史预检数据库。默认文件名形如 `RATools_precheck_results_时间戳.csv`。

<a id="audit"></a>
## 导出最近批次审计包

1. 等待主批次结束；成功、失败、停止和已形成证据的预览取消都可能留有记录。
2. 打开“日志 → 导出最近批次审计包”。
3. 选择保存目录，等待创建独立的 `RATools_Audit_日期时间_随机ID` 子目录。
4. 保留整个目录，并另行保存对应 PDF 结果及需要的来源记录。

当前只导出主窗口内存中的最近已结束批次，没有历史批次选择器。正在运行时拒绝导出；重试或启动新批后可能替换“最近批次”的对象。需要留档时，在下一批前及时导出，关闭软件前完成归档。

| 文件 | 用途 |
| --- | --- |
| `evidence.json` | 配置、文件前后结构、规则计划/结果、终态和事件 |
| `summary.csv` | 文件级汇总，便于人工查阅 |
| `integrity.json` | 文件大小和 SHA-256 完整性信息 |
| `COMPLETE.json` | 包写入完成的标识及关联信息 |

`COMPLETE.json` 只说明包写入完成，不表示所有 PDF 处理成功。包不包含 PDF 正文或密码，也不代替原文件归档。相对文件名等仍可能含业务信息，应按实际内容管理共享。

哈希核验用于检查包的一致性，不认证发布者身份，也不重新检查当前磁盘 PDF 是否改变。对签名、来源真实性和业务内容的复核需要另行完成。

<a id="verify"></a>
## 核验已导出的包

具备源码环境的维护者可在项目根目录运行下面命令，将示例路径替换为实际包目录：

```powershell
python -B -m ratools_pdf.services.audit_evidence verify "D:\归档\RATools_Audit_实际批次目录"
```

`valid: true` 且退出码 0 表示支持的格式和完整性检查通过。失败时不要手工补齐 `COMPLETE.json`，也不要把部分目录重命名当成成功包；应保留问题记录并在可用时重新导出。

这是一条源码维护命令，不表示发布 EXE 有同名通用命令行入口。完整格式和核验规则见[审计证据说明](../audit-evidence.md)。

## 一次实用的交付复核

确认输入数、成功数和未成功原因；打开实际输出；检查页数、重点页面、字体、书签、链接和附件；保留本批配置与日志。需要结构化证据时再导出审计包。软件结果与业务批准应分别记录。
