# 文件级优化与输出

[返回手册首页](index.md)

入口：左侧“文件级优化与输出”。本页有 PDF 版本、线性化、压缩卡片和输出文件名格式化。压缩不保证每个 PDF 都变小；选择前先区分结构压缩和图像降采样。

<a id="version"></a>
## PDF 版本转换

当前界面将目标固定为 **PDF 1.7**，没有任意版本选择框。功能调用 qpdf；完整 Windows 发布包应保留对应资源。

修改 PDF 版本不等于转换成 PDF/A，也不等于所有高版本特性都已按某项标准验证。输出后查看实际版本及关键内容。

<a id="linearization"></a>
## 启用线性化（快速网页浏览）

调整 PDF 的内部组织，以便支持相关功能的阅读器/服务在下载未完成时更早显示页面。它不负责上传文件，也不保证所有网站都按流式方式提供 PDF。

当前处理在标题为空时还会尝试以输入文件名补全标题；如果同时选择清空元数据，应以最终输出属性为准。

线性化会重写结构，文件体积不一定减小。需要保持数字签名的原始有效性时，不应随意重写签名文件。

<a id="lossless"></a>
## 无损压缩级别

| 界面档位 | 组合的规则 | 适用方向 |
| --- | --- | --- |
| 不压缩 | 不选这组结构压缩规则 | 本次没有结构压缩需求 |
| 智能无损 | 标准文件压缩 + 生成对象流 + 无损重压缩内容流 | 先尝试减少对象和压缩流开销 |
| 极限无损 | 深度文件压缩 + 生成对象流 + 无损重压缩内容流 | 进一步清理对象和内容结构，需要复核复杂页面 |

这些档位不是四个可独立组合的可见勾选框。“不压缩”只关闭本组规则，其他已选规则仍可能重写 PDF，不能据此承诺输出字节不变。

“标准文件压缩”清理冗余对象；“深度文件压缩”使用更深入的垃圾回收与内容清理；“生成对象流”将适合的对象组织成压缩流，需 PDF 1.5+；“无损重压缩内容流”重新压缩已有流。这些操作以结构优化为目标，不主动采用图像降采样参数，但仍应检查复杂 PDF 的实际输出。

<a id="images"></a>
## 压缩内嵌图像（扫描件降采样）

这是独立的**有损**选项，可与无损档位组合。勾选后显示 DPI 和 JPEG 质量。

| 参数 | 可选值 | 如何理解 |
| --- | --- | --- |
| 目标 DPI | 150、200、300，或自定义 72–600 | 相同页面呈现尺寸下，较低值通常保留更少像素 |
| JPEG 质量 | 1–95，默认 85 | 较低值可能更小，但更容易产生压缩痕迹 |
| 初始 DPI | 默认 300 | 不是对所有业务文档的推荐或法规要求 |

操作顺序：

1. 先尝试“智能无损”，确认体积是否已足够。
2. 若扫描图像仍占主要体积，在副本上勾选图像压缩。
3. 按实际用途选择 DPI 和质量，不确定时先保持较高质量。
4. 执行后比较体积，放大检查最小文字、签字、印章、细线、图例和扫描底纹。

DPI 根据图像在页面上的实际呈现尺寸计算，不是按整页 A4 尺寸一律缩放；同一图像在多处复用时会考虑不同呈现位置。低分辨率原图不会靠提高目标 DPI 获得真实细节；不支持或无法可靠判断的图像可能保持不变。

如果文件处理成功但没有明显变小，可能原图已较小、压缩充分或本次并未对其降采样。请看实际变化记录，不要把已选择规则当作已发生压缩的证明。

<a id="filename"></a>
## eCTD 文件名合规格式化

此规则作用于输出文件名：转小写、将空格换成连字符，移除不属于 ASCII 字母、数字、下划线或连字符的字符；扩展名转小写。

```text
Study Report 01.PDF → study-report-01.pdf
研究报告.pdf → doc_001.pdf（示例；编号取决于本批顺序）
```

去掉字符后没有可用名称时使用 `doc_编号`。开始前会显示改名清单，请核对；不同源文件若落到同一个目标路径会发生冲突，不能依赖程序替你决定哪个内容应保留。

不同子目录的同名文件可以保留目录身份。文件名格式化不会自动重写所有其他 PDF 指向该文件的引用，也不提供整套 eCTD 目录结构/命名资格验证。改名后应检查跨文件链接。

**覆盖原文件模式的区别：** 当前执行仍写回原输入路径，文件名格式化不会实际重命名原文件；即使前面出现格式化提示，也不能把提示中的名称当作最终磁盘路径。需要生成规范化文件名时，使用默认另存模式并检查实际输出。

## 建议的结果检查

记录输出体积、页数和 PDF 版本；查看典型页面和导航。若体积增大或清晰度不够，使用原件副本调整一项参数后重试，避免对已降采样的结果反复有损压缩。
