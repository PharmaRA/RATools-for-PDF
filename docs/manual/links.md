# 超链接处理

[返回手册首页](index.md)

入口：左侧“超链接处理”。本页操作正文页面中的链接区域。只想检测 Word 导出后的错误文案，应使用[失效引用文本检测](precheck.md#broken-references)。

<a id="paths"></a>
## 绝对路径转相对路径

适用于外部文件链接。当前实现识别绝对路径后保留目标的**文件名部分**，例如把 `D:\资料\附件\report.pdf` 转成 `report.pdf`；它不会自动计算 `..\附件\report.pdf` 这样的跨层级路径，也不会移动或复制目标文件。

因此，目标文件不在预期的相邻位置时，转换后可能无法打开。执行前先明确最终文件布局，处理后在最终输出目录中实际点击外部链接。不要仅看到路径不再含盘符就认为跨文件导航已修复。

<a id="zoom"></a>
## 超链接设为承前缩放

调整受支持的内部、命名目标和外部 PDF 页跳转的缩放信息，减少点击链接后突然切换倍率。它不改变文字字号，也不对普通网页设定浏览器缩放。

复核时先将页面放大，分别点击内部和外部 PDF 链接，确认目标页、位置及缩放符合预期。

<a id="new-window"></a>
## 链接动作：新窗口打开

当前实现为受支持的外部 PDF/文件动作设置新窗口标记。网页 URI 的打开方式仍受阅读器和浏览器控制，不能据此保证所有网页独立开窗。

<a id="blue-text"></a>
## 链接文本设为蓝色

尝试识别链接区域内文本并改为蓝色，让可点击文字更明显。PDF 文本与绘图对象的组织方式可能复杂；扫描图像中的文字不是普通文本对象。

先在包含正文、表格和多行链接的代表性页面试用，检查文字是否完整、颜色是否只影响预期区域，以及链接是否仍可点击。

<a id="black-border"></a>
## 链接区域加黑框

为链接区域设置黑色实线边框，便于识别点击范围。边框可能影响密集表格和相邻正文的视觉效果；跨行链接应检查每行的实际可点击位置。

<a id="bordered"></a>
## 标准化有框链接

对已有边框的链接统一为蓝框黑字风格。它按链接现有状态筛选，不是给所有无框链接统一加框。

<a id="unbordered"></a>
## 标准化无框蓝字链接

对无边框且文字为蓝色的链接，尝试改为蓝框黑字风格。与上一项组合，可覆盖这两类既有样式；原本无框黑字等其他类型不应假定自动纳入。

<a id="remove-border"></a>
## 清除所有链接边框

移除链接的可见边框，保留链接动作。它不等于删除链接，也不保证同时将蓝色文字变回黑色。

## 怎样选择样式组合

| 目标 | 选择方向 |
| --- | --- |
| 用蓝色文字提示可点击 | 链接文本设为蓝色；根据需要单独决定边框 |
| 统一已有的有框/无框蓝字风格 | 标准化有框链接 + 标准化无框蓝字链接 |
| 保留点击功能但不显示边框 | 清除所有链接边框 |
| 删除跳转并将相应文字变黑 | 使用[内容清理中的去色规则](cleanup.md#uri-black) |

不要同时选择互相抵消的加框、去框或颜色方案；配置校验会拒绝部分冲突组合。蓝框黑字两条标准化规则可以成对使用。

要批量改目标地址、交换已有链接数据，见[链接 JSON](data-exchange.md#links)。仅修改样式不会验证目标文件或网页业务内容。
