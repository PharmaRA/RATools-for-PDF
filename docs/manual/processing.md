# 执行批处理：计划、停止、跳过与性能

[返回手册首页](index.md)

主批处理的输入是本轮确定的队列或明确的子集，规则来自当前各模块选项。完整流程是：选文件和规则 → 选择输出 → 审阅计划 → 确认执行 → 检查终态和实际输出。

<a id="plan"></a>
## 处理计划预览

点击“开始处理”后，按提示处理签名文件选择、文件名格式化确认及输出目录/覆盖确认，随后进入“处理计划预览”。

| 计划列 | 怎么读 |
| --- | --- |
| 文件 / 已选规则 | 当前文件及它下面的各条已选规则 |
| 预检 | 命中、未命中、不支持预检或未知；不能只把未知当作未命中 |
| 计划 | 该文件/规则执行还是跳过 |
| 原因 / 风险 | 选择或跳过原因，以及签名、表单、附件、几何变化等提醒 |

预览只读；点击“取消”会请求停止检查并等待线程退出，不创建主处理输出。确认无误后点击“确认计划并开始”。

预览期间输入文件、规则、图像参数或配置发生变化，会使计划失效。应停止外部编辑并重新生成，不要将旧计划当成对新文件的认可。

## 签名文件提示

检测到签名时，程序允许按提示跳过签名文件或继续处理。继续重写可能影响签名有效性。需要保留签署原件时，应选择跳过，或只对有明确用途的副本操作；详见[签名限制说明](security.md#signatures)。

<a id="stop"></a>
## 停止整批任务

处理中，主开始按钮承担停止操作。点击后可能显示“正在停止...”，程序会等待当前控制点或相关进程结束。

已成功发布的输出不会因为停止而回滚；尚未发布的当前结果会按控制状态处理。停止不是撤销上一批，也不能恢复已经覆盖的原文件。

<a id="skip"></a>
## 串行跳过与并行终止选中项

串行处理时点击“跳过当前文件”，尝试跳过当前任务并继续其他文件。

并行处理时，应在队列选中状态为“正在处理...”的 PDF，再使用对应终止选中项按钮；可以按实际选择终止指定任务。选中文件夹、空白处或非运行状态文件不能代替指定正在运行的文件。

如果输出已经完成原子发布，随后到达的请求无法撤回该输出。单次系统读写或 PDF 引擎调用也不保证即时中断，应以最终状态为准。

<a id="retry"></a>
## 重试失败项

批次结束后有失败项时，“重试失败项”可用。先查看错误原因，处理路径、密码、参数或资源问题，再点击重试；它按当前选项创建一个新批次，不是无条件复用旧计划。

已停止和已跳过不等于失败，不应假定它们全部自动进入重试列表。需要再次处理时，核对队列并明确启动。

每次重试会成为新的最近批次。需要保留失败批次审计证据时，先导出旧批次再重试。

<a id="parallel"></a>
## 并行处理

进入“全局设置 → 处理性能”，勾选“启用并行处理”，设置并行数量。界面从 2 开始，上限根据本机 CPU 情况设置且不超过 4；实际工作数还会根据可用内存和输入大小保守下调。

并行数量是上限，不是保证同时运行的数量。资源信息不可用时可能逐个处理。超大扫描件或资源紧张时，先使用串行有助于判断具体文件行为。

<a id="timeout"></a>
## 每文件超时

同一设置页可设置 0–86400 秒，0 显示为“关闭”。默认关闭；设置保存到本机，并在创建本轮任务时固定。

时限包括文件准备、处理和发布前验证，不只是某个规则的执行时间。超时文件会显示处理失败并说明超时，其他文件可继续。查看结果后可适当增加时限或关闭，再重试失败项。

时限不保证在任意单次操作系统/PDF 引擎调用内部立即返回。网络盘断连或外部设备故障也不能仅靠设置超时消除。

<a id="publication"></a>
## 为什么处理完还在验证

主批处理先写临时结果，再检查保存后能否重开，并比较页数、页面尺寸、旋转、导航、批注、附件等结构事实。检查允许且控制状态仍有效后，才发布到最终输出路径。

验证失败不会用失败的临时 PDF 替换原有结果。临时目录按应用策略移入回收站；若不能回收，会保留并提示位置。程序窗口可能等待后台任务结束后才能关闭。

“保存可重开”与“页面肉眼完全正确”“每条规则独立验证通过”是不同结论。输出后仍要按[结果复核](logs.md#results)检查。

技术细节见[计划与验证](../processing-verification.md)、[处理控制](../processing-control.md)。
