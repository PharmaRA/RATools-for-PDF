# RATools for PDF：qpdf 全量能力图形化规划方案与实施路线图

> 文档编号：PLAN-2026-09-10-QPDF-GUI  
> 目标版本：RATools for PDF v0.8.0 - v1.0.0  
> 对应底层：qpdf 12.3.2 (Windows x64 内置 / Linux / macOS 跨平台支持)

---

## 1. 背景与战略定位

### 1.1 现状与痛点
RATools for PDF 当前基于 **Python + PySide6 + PyMuPDF** 构建，在页面内容级处理（如书签树调整、跨文本超链接承前缩放与新窗口打开、字体嵌入预检与自动化、图像重采样压缩等）方面具备高度成熟的业务逻辑。

然而，在处理更底层的 PDF 物理结构时，单纯依赖 PyMuPDF 会面临以下局限：
1. **页面旋转的“伪旋转”问题**：PDF 的 `/Rotate` 只是一个查看标签，当页面旋转 90°/270° 时，底层内容流和坐标系未变，导致盖章、超链接、打印、OCR 时坐标严重漂移。
2. **缺乏真正的 Web 线性化 (Fast Web View)**：在线审阅与跨网络浏览时，无法生成合规的首屏流式字节范围字典。
3. **零散对象流无法打包**：缺少 PDF 1.5+ 对象流 (`Object Streams`) 打包能力，导致含有大量小对象的合规文档体积居高不下。
4. **底层语法与交叉引用表 (XRef) 容错能力有限**：对于结构非标或尾部截断的受损 PDF，难以做到深度抢救与重建。
5. **细粒度安全与权限矩阵控制繁琐**：对 256-bit AES、明文元数据保留、只读打印与内容提取的精确权限控制不够灵活。

### 1.2 战略价值
`qpdf` 是全球广泛认可的、工业级底层 PDF 结构转换与诊断引擎（以 C++ 编写，成熟稳定）。
当前 RATools 已经在 `plugins/qpdf/` 中内置了 Windows x64 的 `qpdf.exe 12.3.2`，但仅在 `ratools_pdf/pdf/qpdf.py` 中硬编码了 3~4 个命令行参数用于简单的解密和线性化。

**核心目标**：将 qpdf 的**全部核心能力（页面装配、物理展平、无损重构、安全矩阵、图层套印、附件管理、逻辑页码、语法诊断与损坏修复）**，以符合 RATools 医药合规和日常办公体验的高水准交互，完整转化为图形化操作。

## 2. 交互范式决策：三大承载矩阵

避免“机械生硬的命令行参数堆砌”，将 qpdf 能力按用户使用心智划分为**三大承载矩阵**：

```
┌────────────────────────────────────────────────────────────────────────┐
│                          RATools for PDF                               │
├───────────────────┬────────────────────────────┬───────────────────────┤
│ 矩阵 1: 批量规则管线 │ 矩阵 2: 独立交互工具箱     │ 矩阵 3: 深度探针与诊断 │
│ (Batch Pipeline)  │ (Interactive Studios)      │ (Inspector & Repair)  │
├───────────────────┼────────────────────────────┼───────────────────────┤
│ • 无损流重压缩     │ • 页面装配/合并/拆分/倒序  │ • 语法合规性体检 (Check)│
│ • 物理旋转归一化   │ • 图层叠加/底纹套印/水印   │ • 加密与权限透视面板  │
│ • 对象流优化(ObjStm)│ • 高级权限与加密配置面板   │ • 线性化指标分析      │
│ • 注释展平(Flatten)│ • 逻辑页码(Page Labels)编排│ • 结构树/JSON 原生探针 │
│ • 自动化线性化/转版本│ • 嵌入式附件管理器        │ • 损坏 XRef 容错抢救修复 │
└───────────────────┴────────────────────────────┴───────────────────────┘
```

1. **批量规则管线 (Batch Pipeline)**：适合可以作为通用规则批量应用在成百上千个文档上的能力（如展平旋转、对象流压缩、线性化、展平注释）。
2. **独立交互工作台 (Interactive Studios)**：适合需要人工指定参数、拖拽排序、多文件交互、图层选择的单任务或复合任务（如页面提取拆分、套打信头水印、加密权限、页码编排）。
3. **深度探针与诊断 (Inspector & Repair)**：适合合规审查员、IT 管理员和开发者快速排查 PDF 为什么报错、为什么打不开，并进行一键抢救。

## 5. 技术架构与核心工程方案

### 5.1 执行引擎架构设计
必须采用**异步外部子进程驱动模型**，严禁主线程同步阻塞，严禁直接依赖 C-API 导致崩溃传染：

```
                    ┌────────────────────────┐
                    │   PySide6 UI / View    │
                    └───────────┬────────────┘
                                │ QThread / Signal
                                ▼
                    ┌────────────────────────┐
                    │  QpdfTaskController    │
                    │  (任务编排、进度解析)  │
                    └───────────┬────────────┘
                                │ 组装参数
                                ▼
                    ┌────────────────────────┐
                    │   QpdfCommandBuilder   │
                    │ (强类型参数拼装与校验) │
                    └───────────┬────────────┘
                                │ Subprocess / QProcess
                                ▼
┌───────────────────────────────────────────────────────────────┐
│              plugins/qpdf/qpdf.exe (子进程)                   │
│  - 独立进程空间，不卡死 Python GIL                             │
│  - 遇到畸形文档即使 C++ 崩溃也不会波及 RATools 主窗口          │
│  - 退出码状态机：0 (成功), 3 (警告但成功), 2 (致命错误)        │
└───────────────────────────────────────────────────────────────┘
```

### 5.2 状态码与异常管理标准
qpdf 具有严谨的退出状态码体系：
- **Exit Code 0**：完全成功，无任何警告与错误。
- **Exit Code 3**：**警告但输出成功生成**（例如非标生成的 PDF 存在冗余字典键或索引越界容错）。
  - **核心处置逻辑**：不能判为失败！输出文件完全有效，提取 stderr 中的 Warning 内容，在 UI 中标记为黄色“警告完成”。
- **Exit Code 2**：**发生不可恢复错误**（如缺少密码、语法致命损坏无法修复等）。
  - **核心处置逻辑**：捕获 stderr，经过 `format_qpdf_error()` 进行人性化错误转译，抛出详细诊断。

### 5.3 JSON 探针的高性能数据桥接
qpdf 12.x 原生支持 `--json` 输出。
相较于传统正则匹配或文本爬取，直接获取全文档的结构化 AST：
```python
# 核心原理示意：
cmd = [qpdf_path, "--json", input_pdf_path]
proc = subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8")
if proc.returncode in (0, 3):
    pdf_ast = json.loads(proc.stdout)
    # 直接提取结构化信息：
    pages = pdf_ast.get("pages", [])
    encrypted = pdf_ast.get("encrypted", False)
    linearized = pdf_ast.get("linearized", False)
```
这为“PDF 深度体检”和“JSON 探针”提供了坚不可摧的数据底座。

## 6. 四阶段迭代落地路线图 (Milestones)

### Phase 1：批量规则管线深度融合 (基础增强与快速见效)
*目标：在不引入复杂新窗口的情况下，解决核心的几何旋转与底层无损重构问题。*
1. **重构底层调用模块**：
   - 升级 `ratools_pdf/pdf/qpdf.py` 为模块化体系，提供 `QpdfCommandBuilder`、`QpdfRunner`。
2. **扩充规则选项**：
   - 在“页面布局”中新增：`flatten_rotation`（展平旋转）、`flatten_annotations`（展平注释）。
   - 在“PDF压缩”中新增：`generate_object_streams`（生成对象流）、`realloc_flate`（无损重压缩内容流）。
3. **集成进 `processor.py` 黄金处理管线**：
   - 先执行 PyMuPDF 书签/超链接/图片重采样 -> 最终由 qpdf 进行底层物理展平、对象流打包与线性化写入。
4. **单元测试与预检**：
   - 编写针对旋转展平与对象流的自动化测试，确保 100% 覆盖。

### Phase 2：页面装配与拆分工作台 (高频交互能力)
*目标：打造所见即所得的多文档合并、拆分、重排与页面提取面板。*
1. **实现高级页面语法解析器**：
   - 支持 `1-5`, `8`, `z-1`, `odd`, `even`, `:rotate=90` 与图形化界面的双向联动。
2. **开发 `PageAssemblyDialog`**：
   - 树状列表/表格支持多文件拖拽拖入、顺序调整（上移/下移）。
   - 提取模式 vs 分卷拆分模式选项切换。
3. **利用 PyMuPDF 提供轻量级缩略图预览**：
   - 在右侧或悬浮框中实时查看页面范围对应的页面缩略图。

### Phase 3：安全权限中心与图层套印管理器 (专业合规与商务套印)
*目标：提供行业顶级的 256-bit AES 细粒度权限控制与公章/信头纸套打功能。*
1. **开发 `SecurityConfigDialog`**：
   - 用户密码/所有者密码双输入。
   - 细粒度权限矩阵（打印等级、修改等级、辅助功能、内容提取勾选）。
   - 元数据明文保留选项。
2. **开发 `OverlayUnderlayDialog`**：
   - 前景 Overlay（印章/草稿水印）与背景 Underlay（信头纸套打）模式。
   - 页面重复匹配规则（单页重复、1:1 页码匹配、模数循环）。

### Phase 4：PDF 深度体检、语法探针与灾难恢复 (诊断工具箱)
*目标：为合规与技术排障提供终极武器，成为 PDF 领域的“瑞士军刀”。*
1. **实现 `PdfInspectorDialog`**：
   - 一键运行 `--check`，生成可视化体检报告表格。
   - 页面级信息展示（MediaBox、CropBox、Rotate 标签、对象流归属）。
2. **开发 `PdfJsonTreeViewer`**：
   - 基于 `QTreeView` 解析 qpdf `--json` AST，查看底层字典与交叉引用。
3. **受损 XRef 一键重建**：
   - 针对打不开或提示严重损坏的 PDF，提供强制重建并抢救导出的功能。

## 7. 风险评估与应对策略

| 潜在风险点 | 影响面 | 规避与应对措施 |
| :--- | :--- | :--- |
| **超长命令行与文件名空格** | Windows 命令行长度上限 8191 字符；路径含空格时参数分裂 | 1. 严格使用 `subprocess` 的 `list` 形式传递参数，禁用 `shell=True`。<br>2. 涉及大量复杂页面拼装时，利用 qpdf 原生的 `@response-file` 参数列表文件机制，彻底突破命令行长度限制。 |
| **恶性损坏 PDF 引发崩溃** | 畸形文件可能导致底层的解析器出现 Access Violation | qpdf 严格在独立子进程运行。若子进程异常退出，捕获非零退出码并呈现友好提示，**主 GUI 进程绝对安全**。 |
| **临时文件残留与磁盘开销** | 复合操作可能产生中间临时文件 | 采用上下文管理器 (`tempfile.TemporaryDirectory`) 自动清理；并在操作完成后执行安全回收，防止污染工作目录。 |
| **中文与特殊字符编码** | Windows 控制台默认编码可能导致 stderr 中文乱码 | 显式指定 `encoding="utf-8", errors="replace"` 解码子进程输出。 |

## 8. 总结与推进建议

本规划方案全面覆盖了 qpdf 12.x 的所有功能，既保留了 RATools 批量、高效、专注于法规合规的管线优势，又通过独立的专业 Studio 赋予用户前所未有的页面重构与安全诊断能力。

建议按照 **Phase 1 -> Phase 2 -> Phase 3 -> Phase 4** 的节奏分期推进，每期完成均包含完整的自动化测试与文档更新，确保系统稳步演进。
