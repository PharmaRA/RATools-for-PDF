# 取消、超时与资源控制（PD06）

在全局设置的“处理性能”中设置“每文件超时”。`0` 显示为“关闭”，其余值为 `1–86400` 秒。设置在本机保存，下次启动恢复；无效的保存值回退为关闭。默认关闭，不改变已有批次的时限。每次创建处理 worker 时固定本轮设置。

## 文件截止时间与终态

每个文件在准备输入快照前开始计时，使用单调时钟；系统时间调整不改变截止时间。时限包括准备、Python 子进程处理、输出快照和发布前验证。调度循环每约 100 ms 检查一次，超时终止本文件处理进程并回收其 staging；其他文件继续。

输入/输出快照和计划指纹向现有 1 MiB hash 块与逐页循环传递 stop/skip/deadline 谓词；在这些检查点合作取消并发出相应终态。单个文件读取、fitz 调用或操作系统原子提交不能强制中断。它们返回后会再次检查控制状态。文件到期后不能进入新的发布操作；取消请求和最后一次发布判定共用控制锁。若发布已获得锁，原子提交先完成，随后接受的停止请求作用于尚未发布的任务。

| 情况 | 结构化 outcome | 界面状态与后续 |
| --- | --- | --- |
| 每文件截止时间到期 | `timed_out` | “处理失败”，消息说明超时；可调整设置后重试失败项 |
| 用户停止批次 | `stopped` | “已停止”，不发布当前 staging |
| 用户跳过/终止选中文件 | `skipped` | “已跳过”，串行和并行均按文件路径处理 |
| 引擎返回失败或 worker 异常 | `processing_failed` | “处理失败”，保留旧输出并可重试 |
| 输出容量/访问预检失败 | `resource_preflight_failed` | “处理失败”，说明磁盘空间或输出位置问题 |
| 验证通过且发布成功 | `succeeded` | “处理完成”，沿用 PD02 实际结构证据 |

PD03 导出把 `timed_out` 映射为 `file_timeout`，与 `engine_failure`、`stop_requested`、`skip_requested` 分开。超时前已有的 PD02 字段继续保留；未捕获的事实保持 unknown/not_verified。qpdf 各公共函数自身原有命令时限仍保留，`QpdfResult` 的返回码、stdout、stderr、command 和成功判断契约不变。

## Windows qpdf 进程树

每次 qpdf 命令拥有一个非继承的 Windows Job Object，启用 `KILL_ON_JOB_CLOSE`，不允许后代 breakaway。使用 Win32 `CreateProcessW` 与 `STARTUPINFOEX` 的 `PROC_THREAD_ATTRIBUTE_JOB_LIST`，将 Job 关联包含在进程创建这一原子操作中，随后验证归属并以保留的主线程句柄 `ResumeThread`。即使 Python owner 在创建调用刚返回、尚未执行后续设置时死亡，孩子也已受 Job 控制；不以进程名称查杀。

`HANDLE_LIST` 只允许继承标准输入 NUL 与 stdout/stderr 写端，Job 句柄不继承。输出通过匿名管道读线程收集，不写临时诊断文件；窗口隐藏。系统或宿主不支持创建时 Job 属性时，在创建任何孩子前失败，不降级为无管理启动。该机制需要 Windows 10 或更新版本。恢复失败时关闭 Job、终止并等待挂起进程，再关闭进程、线程和管道句柄。

Job 句柄属于调用命令的 Python 进程。命令正常结束、启动/接管/恢复失败、命令超时都会关闭 Job；Python worker 被取消或崩溃时，操作系统关闭其句柄并终止 Job 中的 qpdf 和后代。受上层 Job 限制而无法接管时，保持 fail closed，提示接管失败；不会尝试全局查杀或逃离上层约束。

Windows 本机受控测试已实际启动专属父子进程，并验证命令超时、Python owner 终止、批次停止、串并行跳过会收尾父子树，同时无关进程继续存活；另覆盖创建刚返回、后续 Python 设置尚未执行时 owner 退出。归属确认拒绝和恢复失败的路径通过受控故障注入验证；不能据此宣称真实外部嵌套 Job 拒绝或所有宿主策略均已获资格。

非 Windows 源码路径使用独立进程组，在命令结束/超时时收尾。该平台的 Python owner 崩溃和外部宿主策略没有在本次 Windows 环境完成资格验证。

## 并行上限与输出预检

用户选择的并行数是上限。启动批次时读取当前可用内存和各输入字节数，以“每任务至少 256 MiB 或最大输入的 8 倍”估算，只分配可用内存的一半；结果至少为 1，且不超过用户上限。内存读数或输入尺寸不可用时回退为单任务。该估算是保守调度机制，不能代替代表性大文档的实际峰值内存资格验证。

每个文件分配 staging 前检查输出所在卷可用空间，要求至少 64 MiB 或该输入的 3 倍。空间不足时说明如何释放空间/换位置；输出访问失败时提示检查磁盘或网络连接。预检无法保证操作期间设备持续可用；后续访问/提交失败继续保全旧输出。

## 输出与外部资格边界

只有处理成功、保存重开与结构验证允许、未停止/跳过/到期且输入计划仍有效的 staging 才能原子发布。失败与取消不触碰之前成功输出；回收失败保留 staging 并在本机消息中给出位置，供用户处理。窗口退出的既有线程生命周期守卫继续生效。

测试入口仅使用 `python -X utf8 -X faulthandler -B scripts/run_tests_safely.py`。辅助脚本和 PDF 位于该入口的安全临时目录，清理移入回收站。网络设备断连、真实网络盘/移动设备 I/O、生产大 PDF 内存峰值以及外部受限 Job 宿主均属于外部资格工作；本次本机合成 PDF、受控子进程与故障注入不构成这些外部资格通过证据。
